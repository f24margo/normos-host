# ARCHITECTURE & HOST SPECIFICATION: NormOS System

## 1. Общий обзор архитектуры

NormOS построен по модульному принципу с четким разделением ответственности (Separation of Concerns):
1. **Host Layer (Приложение/Сервер):** Точка входа, веб-интерфейс, маршрутизация и REST API.
2. **Services Layer (Ядро обработки):** Набор изолированных сервисов для синтаксического разбора, морфологии, разметки слоев и сборки норм.
3. **Packages Layer (Языковые и нормативные пакеты):** Изолированные словари, индексы и карточки МСУ (например, `packages/msu_ua/`).
4. **Data Layer (Данные и очереди):** Хранилище очереди кандидатов OOV и пользовательских документов.

## 3. Детальное описание сервисов (`services/`)

### `services/registry.py`
* **Назначение:** Единая точка доступа к нормативным базам.
* **Функции:**
  * Чтение `by_verb.json`, `by_agent.json` и карточек из `packages/msu_ua/`.
  * Кэширование индексов в памяти для высокого быстродействия.
  * Ведение и обновление очереди `data/oov_queue.json`.

### `services/parser.py`
* **Назначение:** Предварительная подготовка и синтаксический разбор текста.
* **Функции:**
  * Нормализация символов (апострофы, регистр).
  * Разделение текста на нормативные клаузы с учетом союзов и наличия субъекта после запятой.

### `services/markup.py`
* **Назначение:** Разметка текста на физические слои для визуализации.
* **Функции:**
  * Детекция глаголов (Verbs).
  * Детекция модальных маркеров NKS-012 (OBL, PERM, PROH).
  * Детекция ролей (Roles) по падежным формам.
  * Генерация спанов (Spans) для подсветки в веб-интерфейсе.

### `services/triplets.py`
* **Назначение:** Сборка семантического ядра нормативного акта.
* **Функции:**
  * Выбор главного субъекта клаузы по правилу **Nominative Priority** (Именительный падеж).
  * Генерация триплетов вида $\langle \text{Субъект}, \text{Модальность}, \text{Действие} \rangle$.
  * Декомпозиция **1-к-N** для однородных сказуемых.
  * Обработка безличных предписаний (`subject: null`).
  * Проброс процедурных зависимостей (`depends_on`).

### `services/recommender.py` (Движок подсказок)
* **Назначение:** Автоматический анализ контекста и выдача юридических рекомендаций.
* **Функции:**
  * Подсказки пропущенных процедурных шагов (на основе `depends_on`).
  * Предупреждения об отсутствии субъекта в обязательствах (`OBL`).
  * Автодополнение ролей и глаголов из нормативного пакета при вводе текста.

### `services/exporter.py`
* **Назначение:** Сохранение результатов анализа.
* **Функции:**
  * Генерация автономных HTML-документов с вшитыми CSS-стилями слоев.
  * Экспорт структурированного JSON с триплетами и метриками.

  💡 Куда привязать Подсказки (Рекомендации)?Подсказки — это не отдельная визуальная нагрузка, а аналитический слой поверх триплетов.Они логически идеально выделяются в отдельный модуль services/recommender.py, и вот почему:К чему привязываются подсказки:Привязка к Триплету: Если сформирован триплет $\langle \text{Рада}, \text{OBL}, \text{прийняти рішення} \rangle$, привязанный к карточке N04, движок подсказок смотрит на depends_on: ["N02"] и формирует рекомендацию: «Перевірте наявність кворуму (N02) перед голосуванням».Привязка к Структуре: Если клауза содержит модальность OBL (обязанность), но subject: null, подсказка предупреждает: «Обов'язок без вказаного суб'єкта — рекомендується уточнити виконавця».Привязка к Редактору (Шаг 6): При наборе текста в реальном времени подсказки показывают юридически корректные формулировки.Где они отображаются в UI:Не в самом тексте (чтобы не загромождать слои), а в панеле Инспектора под соответствующим триплетом в виде желтых/синих карточек-предупреждений (💡 Порада / Попередження).
